## 3. Step C — detection, established by mutation

A green suite proves the tests pass, not that they still detect. Two campaigns ran at `caf6bed0`,
both through PR10's own mutation runner (`~/pr10-evidence/r10/mutations.sh`, copied as
`mutations/mutations-pr10-recipes.sh` with exactly two lines changed — its worktree root and its
target base — `mutations/runner-diff.log` holds the `diff` and the two files' sha256,
`88f88f76…` and `92c7b44f…`). The runner asserts each anchor occurs **exactly once** in the file,
copies the file aside, patches it with a python script, saves `git diff` of the patched file as
`<name>.diff`, runs **the one test the recipe names** through the wrapper, restores the file from
the `cp` backup and `cmp`s it, and records `rc` (cargo's exit as captured) in `summary.tsv`. Every
chunk log (`mutations/chain-chunk-01..08.log`, `chain-g5-chunk-02..06.log`) ends with
`tree after: 0 paths`, and `git status --porcelain` was empty after every chunk.

**The detection set is the named test, not the full suite.** This differs from G4's campaign, which
ran the full library suite under every mutation. Here "killed" means the recipe's named test failed
(`rc=101`) under the mutation, which establishes that *that test* detects the mutation; "survived"
means the named test passed, which says nothing about other tests, and each survival below is
explained by reading the test that passed. A recipe expected to pass (`sampler-kills-leader-only`,
a fixture reversion that is no witness either way; `torn-registration-both-without-gitdir`, a
test-side recipe) is reported as what it is.
