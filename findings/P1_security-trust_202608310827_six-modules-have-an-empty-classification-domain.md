## Failure sequence

What this finding is *for* is `mechanism` (3)'s guarantee: a topology module cannot reach an effect through a legacy wrapper while enforcement stays green. **It does not hold, and the route that remains is executed.** A module that carries a recorded allow (`src/engine/coordinator.rs` is the one the reviews used; the same holds of every allowed, classified module a topology module can see) defines a macro that emits `pub(super) fn $name(path) { std::fs::write(..) }` and invokes it with a fresh name -> the function compiles under the module's EXISTING allow, so clippy reports nothing and no allowance is added -> the classification domain (`effects::externally_reachable_fns`, through `declared_fns`, `src/effects.rs:767`) reads a literal `fn name` in the source text, and the text spells `fn $name`, so the generated function is neither a classification obligation nor a multiplicity increment -> nothing classifies it and nothing denies it -> the production body of `park_question` in `src/engine/topology/integrate.rs` references it, a topology test calls it and reads back the bytes it wrote. Executed at `1ff88a78` by both lenses of #309's second review, each with clippy at **exit 0** and **185 tests passing**, and re-run at the head this file was restored at:

- **Module keyword, allowance level and function name all substituted** — main lens `01-relocated-macro.patch`, regression lens `regression-evidence/11-macro-sibling-witness.patch`. Controls `01-relocated-literal-name-control.patch` and `regression-evidence/10-macro-literal-name-control.patch`: with the function name written literally the classification census exits **101**, so the census works against a written name and identifier substitution is what defeats it; `regression-evidence/12-macro-deny-control.patch` is the deny control.

Those runs at the restored head are under `~/orch-pr10/facade-escape-evidence/r2-05-after/`. The cause is one thing, it is structural, and it is wider than expansion: every reading here — the placement scan, the fences, the module walk, the classification census, the multiplicity pins — is a hand-written recogniser of source text, and **whatever rustc compiles and a recogniser does not read is in no census**. It has two halves. **What expansion writes**: a source text does not contain a name, a module or an attribute that a macro or an aliased `include!` produces — the three executed routes above. **What the text itself writes and a recogniser misreads**: the fourth review of #309 executed two at `84123789` with no macro and no `include!` — `#[rustfmt::skip]` and `pub(super) mod`, U+200E, `rf4_child;` in `src/engine/attempt.rs`, whose recorded allow the child inherited, and `#[rustfmt::skip]` and `pub(crate) fn`, U+200E, a name in `src/engine/coordinator.rs`, which needed no new file, no new allowance and no record change — each with fmt, clippy and the whole effects suite green while a topology caller wrote its bytes, because three readers split tokens on three different sets of whitespace and none was the eleven code points rustc reads; and its regression lens executed one a level down, a legal `\u{…}` escape longer than the char-literal reader's window, which let a brace out of a literal, closed two `impl` blocks early and had two effectful paths admitted as one (`~/orch-pr10/reviews/rfacade-4/`). **The module-walk half fails open.** A `#[path]` is refused, so it fails closed; a `mod` declaration the walk does not read is refused by nothing — it is a child no guard judges, and the cross-check beside the walk shares the walk's reading and agrees with it. rustc reports none of this: its text-direction lints cover literals and comments, not the space between tokens. Four rounds across #306 and #309 each closed the spelling in front of them and left the next; #309's fourth round closed those three under one definition (below), and the class stands, because these are recognisers of the shapes this tree and its reviews have produced and not rustc's lexer and parser.
