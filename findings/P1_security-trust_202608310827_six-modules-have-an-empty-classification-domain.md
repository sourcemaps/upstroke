## Failure sequence

What this finding is *for* is `mechanism` (3)'s guarantee: a topology module cannot reach an effect through a legacy wrapper while enforcement stays green. **It does not hold, and the route that remains is executed.** A module that carries a recorded allow (`src/engine/coordinator.rs` is the one the reviews used; the same holds of every allowed, classified module a topology module can see) defines a macro that emits `pub(super) fn $name(path) { std::fs::write(..) }` and invokes it with a fresh name -> the function compiles under the module's EXISTING allow, so clippy reports nothing and no allowance is added -> the classification domain (`effects::externally_reachable_fns`, through `declared_fns`, `src/effects.rs:767`) reads a literal `fn name` in the source text, and the text spells `fn $name`, so the generated function is neither a classification obligation nor a multiplicity increment -> nothing classifies it and nothing denies it -> the production body of `park_question` in `src/engine/topology/integrate.rs` references it, a topology test calls it and reads back the bytes it wrote. Executed at `1ff88a78` by both lenses of #309's second review, each with clippy at **exit 0** and **185 tests passing**, and re-run at the head this file was restored at:

- **No module, no new allowance** — main lens, `~/orch-pr10/reviews/rfacade-2/main-evidence/09-inherited-macro.patch`. Control `09-inherited-macro-deny-control.patch`: a `deny` on the generated function makes clippy exit **101** at the write, so the inherited allow is what admits it.
- **Module keyword, allowance level and function name all substituted** — main lens `01-relocated-macro.patch`, regression lens `regression-evidence/11-macro-sibling-witness.patch`. Controls `01-relocated-literal-name-control.patch` and `regression-evidence/10-macro-literal-name-control.patch`: with the function name written literally the classification census exits **101**, so the census works against a written name and identifier substitution is what defeats it; `regression-evidence/12-macro-deny-control.patch` is the deny control.
- **An aliased `include!`** — main lens `05-aliased-include.patch`: `use std::include as rf2_read; rf2_read!("rf2_review.inc");` brings in a `.inc` holding an allowed inline module and its effectful function. Control `05-literal-include-control.patch`: the literal spelling exits **101** from `effects::tests::no_scanned_source_includes_a_file_no_scan_reads`, which recognises the word `include` before `!` and not the macro a name resolves to.

Those runs at the restored head are under `~/orch-pr10/facade-escape-evidence/r2-05-after/`. The cause is one thing and it is structural: every reading here — the placement scan, the fences, the module walk, the classification census, the multiplicity pins — reads source text, and a source text does not contain a name, a module or an attribute that expansion writes. Four rounds across #306 and #309 each closed the spelling in front of them and left the next.

## What the change that takes this up should do

Owner, as the ledger records it: project owner — **the post-v0.2 pass over PR3's layer**. The second review of #309 names what a real fix needs: *an enforced restriction or expansion-aware classification* on the allowed legacy modules. That is an architecture decision, not a scanner extension, and #309 deliberately does not attempt one. `#![forbid(..)]` is rustc's text-independent mechanism and does not fit here: the witness's effect is compiled inside the allowed module, outside its caller's lint scope, and a file-level `forbid` with per-site `allow`s in the same file is `E0453`.

**Closed, and held by tests, so the next pass does not redo it.**

- By #306: the domain is derived from `production_code` rather than the truncating region; the 62 names that added are classified against a stated module-closed rule; every library record carries a real crate path; the five nameable effectful engine wrappers are denied by path; `src/engine/topology.rs` and the five children of the facade that write no allow deny all three governed lints, and `every_child_the_engine_facade_declares_re_denies_or_records_what_it_inherits` walks the facade's declarations recursively.
- By #309: **the facade's allowance is gone.** The v0.1 conductor's six entry points and their four seams moved, unchanged, into `src/engine/coordinator.rs` and `src/engine/resume.rs`; the facade re-exports the six, denies the three governed lints at file level, and **holds no code** — its leading attributes, `mod x;` declarations and `use` re-exports only, by whitelist (`the_engine_facade_allows_no_governed_lint_and_refuses_both_escape_routes`, `a_declaring_module_holds_declarations_and_re_exports_and_nothing_else`). Its allowlist row and its `FROZEN_LEGACY_ALLOWLIST` entry are removed, so the frozen legacy section is what PR5 froze. **Both routes the fourth review of #306 reported are refused by clippy**, exit 101 at the write: an attribute-free inline module in the facade, and a function placed directly in it, private or not (`PR306-FACADE-INLINE-ESCAPE`, whose file is deleted). The facade forms of the expansion escape — `include!`, and a macro substituting `mod` and `allow`, in the facade — are refused by the whitelist. The ten moved functions are classified effectful and denied by path, and all six public entry points are refused from a topology module through their re-exports.
- Also by #309, for names the source writes: a second callable under an already-classified bare name is refused unless its count is pinned (`every_name_more_than_one_callable_bears_is_pinned_by_its_count`), and an effectful name is shared only by bearers of one path, because no record can classify and deny a second one (`an_effectful_name_is_shared_only_by_bearers_of_one_path`); `pub(in path)` and `extern` forms are in the domain.

**Remaining.** The executed routes above, in the allow-bearing legacy modules. **Reasoned, not executed**: the same substituting macro in a file that carries a `deny` rather than an allow — a fenced sibling of the facade, a topology file — overrides that file's fence with an allow `effects::governed_allows` does not read (this was filed separately as `PR309-AN-ALLOW-THAT-ARRIVES-BY-EXPANSION-IS-UNREAD` during #309 and is folded in here: it is the same cause, the same owner and the same decision, and a second label for one class is how a P1 gets declared fixed under another name); and code carried by a `const` or `static` rather than a `fn`, which stays filed as `PR7-CLASSIFICATION-DOMAIN-READS-FNS-ONLY`.
