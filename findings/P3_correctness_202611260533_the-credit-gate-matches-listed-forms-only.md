## Failure sequence

A pull request of one commit, by a neutral author and committer, credits Claude in a spelling
other than the strings the Contract below lists. Its message ends
`Co-Authored-By : Claude <model@example.invalid>`, with a space before the colon. Neither identity
is a listed one and no line of the message holds a listed string, so the validator exits 0 and
prints `commit-credit-policy: 1 commit(s) checked, none credits Claude`. That is a listed limit.

The other way round, a commit that quotes a listed string in prose is refused. Its body line
`Examples generated with Claude Code include an extra blank line.` holds
`Generated with Claude Code` once ASCII case is folded, so the validator exits 1 and prints
`claude-credit: <full-sha> claude-generated: Examples generated with Claude Code include an extra blank line.`
That is a listed false refusal.

Both are the list's bounds, not evidence that a commit does or does not credit Claude.

### The Contract

As ruling r87 item 3 wrote it, and as the validator's header carries it, word for word:

ASCII case-insensitively, the gate refuses a pull request's own commit when:
- git reports its author or committer email as `noreply@anthropic.com` or ending `+claude[bot]@users.noreply.github.com`, or the trimmed name as `Claude` or `claude[bot]` (r72's question (c): yes, this one identity); or
- its message contains `noreply@anthropic.com`, `Co-Authored-By: Claude`, `Claude-Session:`, `Generated with Claude Code` or `Generated with [Claude Code]`.

Nothing is parsed. Every other spelling passes: a listed limit. A message quoting a listed string is refused: a listed false refusal. The claim is for the workflow's checkout.

Beside the Contract (ruling r116): a commit that declares an encoding (git's `%e` is not empty) is not judged, and the gate stops at exit 2. git may decode such an object before it reports its fields, so what it reports need not be what the object holds.

### The bounds ruling r116 adds

What is compared is git's report of a commit, not the object's bytes. Where a hand-built object makes the two differ, the report governs: a listed limit. Round four's case 4 is one.

The claim is for the workflow's checkout. Fixtures also pin a direct run: replace refs are ignored; grafts, shallow or missing history and a missing commit a promisor could supply are exit 2; and `log.showSignature`, `i18n.logOutputEncoding` and `i18n.commitEncoding` change no verdict. Any other local configuration or environment is outside the claim: a listed limit.

A contributor whose git writes an `encoding` header is stopped at exit 2 until the commit is rewritten without it: a listed closed failure.

### How it got here

[Ruling r72](https://github.com/sourcemaps/upstroke/pull/431#issuecomment-7183591095) closed the
gate's claim to a list of four parsed forms and filed this finding, a deferred P3, for what that
list let pass, including round three's two witnessed limits, which both passes graded P2.
`reviewed_sha` and `location` are where round three found them: the revision's
[name matcher at line 283](https://github.com/sourcemaps/upstroke/blob/9279c8370dd4c24d4c195ac2809fd785e401aa61/.github/scripts/validate-pr-commits.sh#L283),
beside its
[footer matcher at line 285](https://github.com/sourcemaps/upstroke/blob/9279c8370dd4c24d4c195ac2809fd785e401aa61/.github/scripts/validate-pr-commits.sh#L285).
Round four found two P2s and five P3s in and around that grammar: a co-author's comment, a linked
footer, the graft file, a raw header, the fixtures' environment, the committer email fixture and
the body's count of old credited commits. Ruling r87 item 3 replaced the grammar with the fixed
strings of the Contract above. Round three's two witnessed limits now each hold a listed string
and are refused: the footers behind the keycap and sparkle emoji hold
`Generated with [Claude Code]` and `Generated with Claude Code`, and the co-author lines naming
`Claude-Opus` and Claude, a no-break space, Code hold `Co-Authored-By: Claude`. Those verdicts
are read from the validator; the witnesses were not run again.

Before the last review pair, the driver's mutation matrix and a probe of git's configuration found
three claims no fixture reached (the identity count and the replace-ref and lazy-fetch exports),
and two reads that passed a listed form (under a UTF-7 output encoding, and on a commit declaring
an encoding). Ruling r116's run pinned the first three with fixtures and repaired the two reads,
each with its fixture.
